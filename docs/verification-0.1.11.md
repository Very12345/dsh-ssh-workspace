# 0.1.11 验证

2026-10-17 的真实环境中，系统 OpenSSH 可以登录，桌面插件 catalog/status HTTP 接口正常，但目录浏览会等待远端 CLI 启动。CLI 正在尝试解析／下载较新的 stable Server；远端 curl 独立检查返回 Resolving timed out。

远端插件目录已经存在固定提交 07f806f999227108933c2e30515b26eecc1fda74 的 Server 1.140.0。旧逻辑先运行 CLI 在线启动，最多等待十分钟，再查找仅限 ~/.vscode-server 的备用缓存；它忽略了插件自己的已验证缓存。

修复在三个维护的 provider snapshot 中共享启动策略：

- 默认 CLI 及插件初始化生成的 CLI 路径先复用已验证的插件缓存，再进行 AHP 协议协商。
- 不兼容的候选会关闭其所属进程和隧道，继续尝试；保留认证与主机密钥校验。
- 显式自定义 CLI 不被其他缓存取代；在线 CLI 单次启动最多 45 秒。
- 错误指出 Agent Host／DNS／下载这一层，诊断脱敏端点令牌。
- 前端网络错误和无效 JSON 响应给出明确说明，取消请求保持原有语义。

验证：

- 46 项单元与真实 SDK 测试全部通过。
- 原生目录选择器与设置页 UI smoke 通过，客户端已重新构建。
- 真实 SSH + AHP 只读目录浏览约 4.5 秒完成，返回 24 个目录。
- 探测使用独立本机临时状态，销毁自己建立的连接，不写远端项目文件，不改系统 DNS。

此处只证明兼容缓存可以绕过在线下载故障，不代表远端 DNS 已修复或全新环境可以离线初始化。
